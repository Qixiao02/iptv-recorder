## 2. 核心模块设计

### 2.1 配置管理 (config.rs)

**职责**: 加载和管理应用配置

**设计要点**:

- 分层配置: 默认值 → 配置文件 → 环境变量
- 支持 TOML/YAML 格式
- 环境变量使用 `IPTV__` 前缀，双下划线分隔嵌套

```rust
// 配置优先级示例
// 1. 环境变量: IPTV__SERVER__PORT=8080
// 2. 配置文件: [server] port = 3000
// 3. 默认值: 3000
```

### 2.2 数据库层 (core/database.rs)

**职责**: 数据库连接管理和初始化

**设计要点**:

- 使用 SQLite 作为存储引擎
- 连接池管理（默认最大 10 连接）
- 自动运行数据库迁移
- WAL 模式支持并发读写

**表结构**:

- `channels` - 频道信息
- `schedules` - 录制计划
- `tasks` - 任务实例
- `recordings` - 录制进程

### 2.3 事件总线 (core/event.rs)

**职责**: 模块间异步通信

**设计要点**:

- 基于 Tokio broadcast channel
- 支持多订阅者模式
- 消息类型: 任务更新、进度推送、频道状态、系统告警

```rust
pub enum Event {
    TaskUpdate(TaskUpdateEvent),
    TaskProgress(TaskProgressEvent),
    ChannelStatus(ChannelStatusEvent),
    SystemAlert(SystemAlertEvent),
}
```

### 2.4 进程管理 (core/process.rs)

**职责**: 管理外部录制进程生命周期

**设计要点**:

- 异步进程启动和监控
- 双管道捕获 stdout/stderr
- 优雅终止（SIGTERM → 等待 → SIGKILL）
- 孤儿进程清理

### 2.5 业务服务层 (services/)

#### ChannelService

- 频道 CRUD 操作
- 按分组查询
- 状态更新
- 健康检测

#### ScheduleService

- 计划 CRUD 操作
- Cron 表达式解析
- 启用/禁用切换

#### RecordingService

- 手动录制启动
- 任务状态查询
- 任务取消
- 进度更新

## 3. 数据流设计

### 3.1 频道导入流程

```
用户上传 M3U 文件
       │
       ▼
M3U Parser 解析
       │
       ▼
验证 URL 有效性
       │
       ▼
批量写入数据库
       │
       ▼
返回导入结果
```

### 3.2 定时录制流程

```
Cron Scheduler 触发
       │
       ▼
检查频道在线状态
       │
       ├─ 离线 → 跳过本次，记录日志
       │
       ▼ 在线
检查并发限制
       │
       ├─ 已满 → 加入等待队列
       │
       ▼ 可用
创建任务实例
       │
       ▼
启动录制进程
       │
       ▼
监控进度/状态
       │
       ▼
进程结束 → 更新任务状态
```

### 3.3 实时状态推送流程

```
录制状态变更
       │
       ▼
RecordingService 发布事件
       │
       ▼
Event Bus 广播
       │
       ▼
WebSocket Handler 订阅
       │
       ▼
推送消息到客户端
```

### 4.2 任务优先级

```
优先级 = 基础优先级 + 时间紧迫度 + 频道重要性 - 历史失败率
```

## 5. 错误处理策略

### 5.1 错误分类

|错误类型 |处理策略 |
|---|---|
|源流 404 |标记频道离线，暂停后续任务 |
|网络超时 |指数退避重试（1s, 2s, 4s...） |
|磁盘满 |暂停所有新任务，发送告警 |
|进程崩溃 |根据配置决定是否重试 |

### 5.2 降级策略

- 检测到连续失败 → 降低该频道优先级
- 资源不足 → 暂停低优先级任务
- 服务过载 → 启用请求队列
